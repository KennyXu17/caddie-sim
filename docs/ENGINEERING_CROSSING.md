# 小机器人换边（车道左右侧）工程方案

## 问题

同一车道左右两侧：左侧走廊 `x = -22`（服务 1–7, 15–19, 25–29, 35–39），右侧走廊 `x = 20`（服务 8–14, 20–24, 30–34, 40–44）。机器人若在 25–34 的 charge point 侧（例如右侧），需换到 35–44 的 charge point 侧（或反向）时，如何**尽量不违反交规、保证安全**地穿越车道？

---

## 工程上的常见做法

### 1. 指定换边点（Designated Crossing Points）— **本项目采用**

- **做法**：只在固定位置穿越车道，例如固定 `z` 的“换边点”：`z = -8.5`、`z = -21`（与现有走廊转向点一致）。
- **规则**：
  - 换边仅允许在 `(-22, z)` ↔ `(20, z)` 之间进行，`z ∈ {-8.5, -21}`。
  - 穿越时**保持 z 不变**，仅改变 x（垂直于车道方向），避免斜穿。
- **优点**：路径可预测、易验证；类似“在指定位置过马路”，符合交规直觉。
- **实现**：去程/返程若需换边，先到当前侧换边点 → 可选“ yield ”短停 → 直线移至对侧同 z → 再沿对侧走廊行驶。

### 2. 掉头式换边（U‑turn Style）

- **做法**：在车道端头或指定区域做 180° 掉头，然后沿对侧走廊行驶。
- **优点**：不横穿车道中段，更贴近“车辆掉头”语义。
- **缺点**：需明确掉头区几何与通行规则；路径更长。

### 3. 环线绕行（Loop / No Direct Cross）

- **做法**：不直接穿越车道。机器人驶出当前侧 → 经入口/环岛等绕行 → 从对侧走廊入口驶入。
- **优点**：完全避免车道内横穿。
- **缺点**：路径长、逻辑复杂，需额外规划绕行路线。

### 4. 分区调度（Zone Dispatch）

- **做法**：将 25–34 与 35–44 分为不同服务区，机器人优先服务本区；仅在本区无车或负载均衡时才跨区，且跨区必须经**指定换边点**换边。
- **优点**：减少换边频次，便于安全与调度管理。

---

## 安全性要点（尽量不违反交规）

1. **仅限指定位置换边**：禁止在非换边点横穿车道。
2. **垂直穿越**：换边时固定 z，只改变 x，避免斜穿、缩短暴露时间。
3. **Yield 再通过**：换边前短暂停顿（如 1s），模拟“观察来车、确认安全后通过”。
4. **预留/避碰**：换边路径参与 `reservePath` / 碰撞检测，与其他车辆、机器人不冲突后再执行。

---

## 本项目实现概要

- **换道点**（行）：第一行 `z = -25`，第二行 `z = -21`，第三行 `z = -8.5`，第四行 `z = -4.5`；左右走廊 `x = -22` 与 `x = 20`。第一行 `(-22,-25)`/`(20,-25)`，第四行 `(-22,-4.5)`/`(20,-4.5)`，第三行 `(-22,-8.5)`/`(20,-8.5)`。
- **同行**：前往同一行 charge point 不经过换道点；若换边则仅在该行换道点垂直穿越。
- **跨行**：例如从 33 的 CP 到 5 的 CP：先到第三行换道点 `(20,-8.5)`，再到第一行换道点 `(20,-25)`，最后到目标 CP；换边时在目标行换道点穿越。
- **换边**：仅于对应行换道点垂直穿越；穿越前 yield，并参与路径预留与避碰。
- **旋转**：小 caddie 移动方向按逆时针 90° 修正（`rot = atan2(dx,dz) + π/2`）；已移除机械臂与充电逻辑。

详见 `main_sim.js` 中 `chargeVehicle` 的 `ROW_CROSSING_Z`、`waypoints`、`needsCross`、`addCrossing` 及 `addPathSegment`。
